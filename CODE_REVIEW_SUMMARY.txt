                        🔴 CRITICAL ISSUES
================================================================================

1. ATTENDANCE LOGIC INVERTED — REVENUE LOSS
   File: src/app/api/attendance/[lessonId]/route.ts (line 142)
   Status mapping backwards: no-shows marked as present, credits NOT burned
   Impact: Students don't attend → credits refunded. Schools lose revenue.
   Fix Time: 15 min
   Action: Invert: burns_credit ? 'no_show' : 'present'

2. STRIPE WEBHOOK ACCOUNT ISOLATION MISSING
   File: src/app/api/webhooks/stripe/route.ts
   No verification: webhook from school A with school B's metadata processed
   Impact: MULTI-TENANT BREACH - one school can modify balances at another
   Fix Time: 20 min
   Action: Validate event.account matches school's stripe_account_id

3. STRIPE METADATA TYPE MISMATCH
   File: src/app/api/stripe/checkout/route.ts (line 143)
   Stores user.id (auth) but DB expects students.id
   Impact: Payment processing broken. Credits go to wrong student.
   Fix Time: 30 min
   Action: Store students.id not auth.users.id in metadata

4. UNRESTRICTED SCHOOL ADMIN PATCH (MASS ASSIGNMENT)
   File: src/app/api/hq/schools/[id]/route.ts (line 22)
   Accepts arbitrary fields: platform_fee, stripe_account_id, active, user_id
   Impact: HQ staff can hijack Stripe accounts or bypass platform fees
   Fix Time: 20 min
   Action: Implement field whitelist + sub-role permission checks

5. MISSING RATE LIMITING ON AUTH
   Files: /api/auth/register, /api/auth/send-reset
   No rate limiting on password reset/registration
   Impact: Account enumeration, brute force, mass registration (DoS)
   Fix Time: 45 min
   Action: Add IP-based rate limiter (5-10 req/min) with @upstash/ratelimit
