#### TCH-R4-01 — Attendance marking still returns 500 for three malformed body shapes (teacher and school endpoints) — R3-M8 PARTIAL
- **Where:** `backend/bookings/attendance_views.py` `_apply_marks()` (shared by `TeacherAttendanceView.post` and `SchoolAttendanceView.post`). PR #150 (`86f8fe1`, R3-M8) added `ensure_object_body` so a body that is neither a list nor an object → 400, but the items inside the list are still taken on trust: `raw.get(...)` on a non-dict item raises `AttributeError`, an `attendance` key that is a string is iterated character by character, and a non-UUID `status_id` reaches `AttendanceStatus.objects.filter(pk="y")`, which raises `ValidationError` before the `invalid_status_id` branch.
- **Repro (T1 token, own past lesson `b494a3f3…`; identical as the school owner on `/api/school/attendance/b494a3f3…/`):**
  - `POST /api/teacher/attendance/b494a3f3-a3e5-4dca-9a7b-70576e942b68/` body `{"attendance":"x"}` → **500** (Django "Server Error (500)" HTML, no traceback)
  - body `[1,2]` → **500**
  - body `[{"student_id":"x","status_id":"y"}]` → **500**
  - body `[{"student_id":"bb32cfc3-8883-4220-a40c-bb0392ce38f2","status_id":"y"}]` (valid student, non-UUID status) → **500** (school endpoint)
  - control: `"hello"`, `123`, `null` → **400 `{"detail":"Expected a JSON object or array as the request body."}`** (the part R3-M8 fixed); `{"attendance":[{"student_id":null}]}` → 400.
- **Expected:** 400 with a field error, like the sibling cases.
- **Impact:** a client bug (e.g. a status id that is not a UUID) turns into a 500 with Sentry noise; no data written, no traceback leaked. Medium because it is the register's main write endpoint and R3-M8 was reported fixed.
- **Evidence:** `$SP/work/teacher/11-attendance-api.js` and `14-staff-grants.js` run logs (transcribed in §5 notes); roster verified unchanged after each probe.
- **vs R3:** R3-M8 **PARTIAL** on this endpoint (X-R3-06 listed the body-type case only).

#### TCH-R4-02 — A teacher can set her own `photo_url` to any URL (rendered as `<img src>` to every student) and flip her own `active` flag — NEW (sibling of R3-M10)
- **Where:** `backend/teachers/serializers.py:24-27` — `TeacherSerializer.Meta.fields` includes `photo_url` and `active`, `read_only_fields = ("id",)`; `backend/teachers/views.py:54-91` `TeacherProfileView.patch` passes `request.data` straight into it. The only sanctioned way to set a photo is `POST /api/teacher/<id>/image/`, which after R3-C2 validates the bytes — this second path bypasses it entirely.
- **Repro (T1 token):**
  - `PATCH /api/teacher/profile/ {"photo_url":"javascript:alert(1)"}` → **200**, stored.
  - `PATCH /api/teacher/profile/ {"photo_url":"https://evil.example/x.png"}` → **200**, `GET /api/teacher/profile/` → `"photo_url":"https://evil.example/x.png"`.

Medium: mass-assignment on a self-service endpoint with a cross-role rendering consequence, same class as R3-M10.
- **Expected:** `photo_url` and `active` read-only on the self-profile serializer (the upload view writes `photo_url` itself); optionally the R3-L10 URL validator on any URL field.
- **Evidence:** `$SP/work/teacher/21-profile-isolation.js` log; `$SP/work/teacher/state.json` (`t1_photo_url`).
- **vs R3:** NEW.

#### TCH-R4-10 — A month recorded as paid keeps showing "Pagato" after later attendance raises the total: the teacher sees "€65.00 · Pagato" while the school paid €40 — NEW
- **Where:** `TeacherCompensationOverviewView` (`backend/teachers/views.py:253-360`) returns `total` (recomputed from attendance) next to `payment {amount, status}` (a static row); `frontend/src/app/[locale]/teacher/compensation/page.tsx` renders the school card with the recomputed total and the payment **status** badge only — the paid amount is not shown and there is no partial / outstanding state.
