## Aperto: il deploy su EC2

Tre deploy consecutivi dei codici sconto sono falliti: il worker SSM moriva
dopo ~75 secondi con `ipc messaging received timeout signal`, portandosi via
anche i log. **Produzione è quindi rimasta a `f37e89e`** (il sito ha sempre
risposto 200: non si è mai rotto, semplicemente non si aggiornava).

Modifiche fatte a `.github/workflows/ci.yml` per uscirne:

- il comando SSM ora **lancia soltanto** lo script, che gira staccato
  (`setsid`) scrivendo su `/var/log/nounder40-deploy-<run-id>.log`;
- l'avanzamento si legge con comandi SSM brevi, e a fine corsa **il log
  completo finisce nell'output del workflow** — prima si perdeva;
- `docker image prune -f` **prima** del pull e pull di un'immagine alla volta
  (le due cause più probabili: disco pieno, picco di memoria).

Da fare al prossimo giro: leggere quel log e capire su cosa si blocca. Se
serve un accesso diretto all'istanza, senza credenziali AWS in locale l'unica
via è il workflow (`workflow_dispatch`).

Verifica veloce se produzione è aggiornata:

```bash
curl -o /dev/null -w '%{http_code}\n' -X POST \
  https://danzaclassicanounder40.com/api/student/discount-code/check/ \
  -H 'Content-Type: application/json' -d '{}'
# 401 = versione nuova online · 404 = ancora la vecchia
```

## Ripartire sul PC nuovo

```bash
git clone git@github.com:ExecutionAI-net/nounder40.git
cd nounder40 && git checkout wip/passaggio-pc
cp .env.example .env          # va riempito: non è versionato
make up                       # stack completo su http://localhost
```

Il database locale **non** viaggia con git. O si riparte da produzione
(`cp .env.sync.example .env.sync`, riempirlo, `make db-pull`), oppure si
ricrea a mano quel che serve: sul vecchio PC c'erano una scuola demo
(`c.carlo@cfcholding.it`), un "Pacchetto Test 10" e il codice `PROMO20`.

Il deploy parte **solo dai push su `develop`**: per mandare in produzione
quello che si fa qui, va riportato là.
